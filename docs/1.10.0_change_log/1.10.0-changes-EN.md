## 1. Version Scope and Method

### 1.1 How the Start and End Versions Were Determined

The repository has no git tags, and GitHub Releases is empty too, so two independent lines of evidence were cross-checked to pin down the 1.9.2 release point:

1. The timestamps of historical build artifacts in `build/libs/`: `shape-shifter-curse-1.9.2.jar` was built on **2026-06-14 12:27**; `1.9.2-nts` on 06-23, and `1.10.0-beta` on 10-26.
2. The commit message of `89901e02` (2026-06-14 17:21) explicitly says "now that 1.9.2 has been released, let's remove the powers that shipped with origins" — that commit and everything after it does not belong to 1.9.2.

Therefore **the 1.9.2 release point = `a96f557d` (2026-06-14 10:52, the last master commit after the `1.9.2` version bump)**, and **the 1.10.0 range = `a96f557d..b6a03f01` (HEAD, 2026-10-26)**.

> Footnote: the version string in `gradle.properties` churned through `1.9.2 → 1.9.2-nts → 1.10.1 → 1.10.0` in July (`06ee398b`, `2312ab11`, `09a78b52`); the latter names were development-period labels, and the final public version is **1.10.0**. Separately, the `form_system_refractor` branch (development started 6-05, merged via PR #457 on 6-23) carries the new transform system; its commits fall inside this range but not inside 1.9.2.

## 2. Overview: The Big Player-Facing Picture of 1.10.0 vs. 1.9.2

**One-sentence summary**: 1.10.0 is not a small content patch but a major release advancing on three fronts at once — "transform system rewrite + form progression gameplay (Perk skill trees / Altar / Form Tuner Beacon) + two new sub-forms + a full localization cleanup" — and it also completes the rendering library migration (AzureLib→GeckoLib), with changes to installation requirements.

### 2.1 New Gameplay (New Things Players Can Do)

1. **Form skill trees (Perk)**: the 3-tier forms of Bat/Axolotl/Ocelot/Fox/Snow Fox/Anubis Wolf/Spider and the two sub-forms each get an independent skill tree (9 trees, 68 nodes in total), unlocked by spending experience points or Glint Prisms, with active skills bound to number keys 1~6. [All players, must first progress to the final form]
2. **Altar + Form Tuner Beacon**: two new blocks forming a new crafting/progression chain. The **Altar** is a transmutation block with "moondust fuel + catalyst slot": 13 basic form trinkets are now crafted here, 12 trinkets can be upgraded to "+", the 7 kinds of Catalyst Core and materials such as Glint Prisms are produced here, and any food can be turned into Morphscaled Food. The **Form Tuner Beacon** is produced by the Altar and opens the form attunement screen on right-click for allocating points; the higher the beacon base is built (1~4 layers), the higher the skill tree tier you can spend points on. [All players]
3. **Form upgrade items (the "+" series)**: 12 old items gain "+" upgraded versions (11 form trinkets + Bottled Snowfall + a handheld tool), obtained by upgrading at the Altar with the matching Catalyst Core (the Catalyst Core is not consumed); there is also 1 new upgrade-chain item, Explosive Charm Paper (Burning Charm Paper + Soul Sand). [All players]
4. **Seven Catalyst Cores + charm paper + new weapons/tools**: Jungle/Web/Frost/Foxfire/Surge/Dune/Night Catalyst Cores; Explosive and potion (healing/damage/poison) charm papers; the Composite Kinetic Bow, Graphene Blade, Ripple Mirror, Web Bullet, Glint Prism, and more. [All players]
5. **Two new sub-forms**: Bat 3's "Avali" and Snow Fox 3's "Marbled Polecat", each with its own appearance, animations, and gameplay (Avali leans toward flight; the Marbled Polecat has long-neck IK and a standing idle). [Players who have that form]
6. **Sub-form selection screen "Mirror Reflection"**: once a form reaches tier 3, you can choose a sub-form. [Form: bat_3 / snow_fox_3]
7. **The Book of the Shapeshifter becomes the only book UI**: the old owoLib book and starter book UIs were deleted together with the config option `enableNewStartBook`; the book gains a new "exclusive trinkets/tools" section and a Cursed Moon icon in the top-right corner, and the book and form scrolls can be placed in chiseled bookshelves. Form Customization Menu V2 already had a complete implementation in 1.9.2; this time only 2 bugs were fixed (sub-form rendering, accent color inversion) plus support for closing it with the E key. [All players]
8. **Active ability hotkeys 1~6**: new keybinds for perk active skills. [All players]
9. **Initial form configuration / Gamerule**: servers can specify the form players start with, and a new `sscUseInitialForm` game rule was added. [Server-side/Modpack]

### 2.2 Mechanic Changes (What Veterans Will Feel Differently)

1. **Transform system core rewrite**: forms became data-driven (DynamicForm/datapack forms), the Instinct logic was redone, form fallback/recovery was added (automatic fallback on login, up to 20 history entries), and Cursed Moon behavior was rewritten (you cannot sleep that night; whether you transform is configurable). [All players]
2. **Rendering library AzureLib → GeckoLib**: GeckoLib 4.x (4.8.4) must be installed, AzureLib/AzureLibArmor are no longer needed, GeckoLib 5.x prevents startup, and the jar no longer bundles a rendering library. [All players]
3. **Form phase naming**: "phase 0/1/2" became "Initial/Phase 1/Phase 2"; the "exclusive trinkets/tools" section in the form book was split out of the long text into a separate field. [All players]
4. **Major localization overhaul**: British English en_gb was completed to 1020 keys and anglicized (the file already existed in 1.9.2 with 494 keys); en_us went through large-scale grammar/terminology corrections; Russian was extended; Chinese rich-text coloring was unified. [All players]
5. **Form body size is now controlled by data/attributes**: all `*_scale.json` powers were deleted (scalePower removed), and some forms were scaled up. [Form: allay_sp / anubis_wolf / axolotl / snow_fox_3 / familiar_fox_3 etc.]
6. **Milk no longer removes the curse**: proper means such as Golden Apples/inhibitors are required, and the UI now says so. [All players]
7. **Multi-layer rendering temporarily removed**: only a single form renderer is rendered per player; appearances that rely on stacked layers are temporarily unavailable, and add-on mods need to adapt to the interface changes. [All players / Add-on authors]
8. **Animation asset format generation change**: the form model's `builtin_controller_data` is replaced by `animation_system`+`animation_system_config`; old resource packs silently stop working (tails/wings no longer move). [Resource pack/form pack authors]

### 2.3 Balance Adjustments (See Section 6 for Details)

About 43 balance commits: water blast (damage/cooldown/cost), Axolotl wetness and regeneration, feral_cat, the cat protection radius, body size increases, cursed Axolotl spawn rate, Golden Apple/inhibitor curse removal, Ocelot pounce conditions, keybind assignment, and more. Item-by-item before→after in 6.1.

### 2.4 Player-Visible Fixes

Of the 175 fix commits, many address issues players had reported for a long time: Instinct bar desync in multiplayer, powers failing after relogging (traced back nearly a year), small forms getting stuck on trapdoors, Axolotl swimming into walls/sitting on chairs, long-neck first-person misalignment, messed-up tails/capes in multiplayer, random server crashes, altar server crashes, perks failing after death and respawn, achievements and chiseled bookshelves, etc. Summary table in 6.2.

### 2.5 Unreleased / WIP (When Writing the Wiki, Do Not Present These as Shipped)

1. **Magic system (key radial / mana)**: the UI, radial menu, mana API, and cape already have code, but in October the author marked "magic system on hold for now" [Unreleased]. Note that `magic/MagicUtils.java`'s `shouldShowMagicUI` currently returns true unconditionally (the comment says "set it to True for now during development"), so the client may show a three-slot radial HUD — that is development leakage, not a playable feature.
2. **Full-form model redo project (from 9-17)**: the new models exist only in the repository's `3d_models/` and are **not exported to the runtime `geo/`**, so players will not see them in 1.10.0 [Unreleased].
3. **Animation speed datachain**: the toolchain is ready, but runtime animation files have no `speed` field yet [Unreleased].
4. **Multi-layer / sub-form layer mounting, patron-exclusive forms**: design document stage [WIP].
5. Leftover test files (`_test_perk01.json`, `form_long_cat_test.geo.json`, `form_axolotl_3.geo.json.backup`, `test_textures.png`, etc.) are still in the asset directories and should be cleaned up before the official release.

## 3. Form System and Forms

> Domain scale: "Forms and transform system" is directly touched by 163 commits (37 fix / 12 balance), `player_form/**` changed 77 files, +3814/−3975 lines; 1.9.2's entire `PlayerFormBase`/`PlayerFormPhase`/dynamic-form legacy system was replaced by `IForm` + `NormalForm`/`NormalGroup` + `Set<String>` flags + an integer tier (PR #457 `form_system_refractor`, merged in `7af3b303`, 2026-06-23), and a sub-form framework, 2 new sub-forms, 4 new commands, initial form configuration, and datapack forms were added. - Form phase naming changed across the board: `(Phase 0/Phase 1/Phase 2/Permanent Phase)` → `(Initial Phase/Phase 1/Phase 2/Permanent Phase)`, synced across Chinese/English/British English/Russian (English `Phase Initial/Phase 1/Phase 2/Phase Permanent`, and the Russian 1/2/3/4 ordering was unified as well) [All players] (`39459dc3`; `lang/zh_cn.json:169-190`; `baseline/lang_diff.md`)

**Cursed Moon**

- The Cursed Moon moved from "hard-coding the before/after phase by phase index" to "record the form before moonrise and after moonrise, and revert per the record at moonset": moonrise records Before/After; at moonset it prompts and reverts only if "the current form is still After"; if during that window a Golden Apple/inhibitor/command changes the form to something else, it is no longer forcibly dragged back [All players] (`4797c344`; `cursed_moon/CursedMoon.java:49-128`; `ITransformReason.java:111-146`)
- Final/special forms no longer show exclusive prompts under the Cursed Moon: the three keys `on_cursed_moon_permanent`, `end_cursed_moon_permanent`, `on_cursed_moon_special` remain in the language files but are no longer referenced by Java, so players only see the generic moonrise message [Players of this form] (`cursed_moon/CursedMoon.java`; old `player_form/transform/TransformManager.java` index 3/5 branch)

### 4.2 Mechanical details

**Perk costs, prerequisites and condition hints**

- The server validates an unlock request in a fixed order: tree matches → perk exists and is inside the tree → affordable (when not free) → all prerequisites met → not already owned → Overworld (tier>0) → "last used Tuner" tier ≥ the node's tier → `canGain` → charge the cost → record and sync the power; creative mode or forms in `freePerkForms` may skip the cost and tier checks (prerequisites and tree matching still apply). (`perk/PerkUtils.java:103-159`)
- Two cost types: XP points (`player.addExperience(-N)`, not levels) and items (counts mergeable stacks across the whole inventory and deducts from it, Glint Prism being the example); the UI amount text is "cost / currently owned", the query runs once per second by default and refreshes 5 ticks after an unlock click. (`util/util/cost/{XPCostType,ItemCostType,IFUSDrawableCostType}.java`, `custom_ui/FormUpgradeScreen.java:215-224,613-629`)
- The "last used Tuner" is stored only in server memory (UUID → BlockPos); it is lost after a server restart, a dimension change or when the chunk containing the Tuner unloads, so the player must right-click a Tuner once more before unlocking further tier>0 nodes. (`blocks/FormAttunerBlock.java:33-44,89-90`)
- A perk's effect adds/removes an Apoli power on the player (data in `data/shape-shifter-curse/powers/perks/*.json`); switching form or relogging replays `onLoad` for every unlocked perk and automatically prunes perks that no longer exist in the tree (editing a tree or deleting a perk does not break saves). (`perk/NormalPerk.java`, `perk/PerkUtils.java:161-173`, `player_form/FormUtils.java:221,246`)

**Tuner tier and beam**

- The tier is decided entirely by the base structure: starting below the Tuner it checks layer by layer whether the (2j+1)² region consists entirely of beacon base blocks; outside the Overworld the tier is simply 0, and it refreshes every 80 ticks (4 seconds); going 0→N plays the beacon activate sound, dropping back to tier 0 plays the deactivate sound, and a tier>0 Tuner plays the ambient sound. (`blocks/block_entity/FormAttunerBlockEntity.java:111-136`)
- Maximum tier 4 (`MAX_LEVEL = 4`); development builds originally went up to tier 10, but this was lowered because "one check covers about 1770 blocks, a server-lag risk", and `allocMaxLevel()` is left for modpack authors to raise the cap. (`907e5f5c`, `FormAttunerBlockEntity.java:26,32-34`)
- The beam reuses the vanilla `textures/entity/beacon_beam.png`: it runs straight up from the Tuner to the build height limit (the last segment is rendered at height 1024), with inner/outer radii 0.2/0.25 and the same animation as a beacon; `Stainable` blocks along the path such as stained glass tint it, and the Tuner itself is pink-purple `{0.902,0.373,0.945}`; no beam is rendered at tier 0. (`0475c915`, `06bf2689`, `blocks/block_entity_renderer/FormAttunerBeamRenderer.java`, `FormAttunerBlockEntity.java:138-140`)
- The screen does not show the "current Tuner tier" directly; it only shows the column dividers for tiers 1–4 and the number at the top of each column (node texture 20×20 per column, column-top number 11×11), and when the current column cannot be clicked it shows the "Tuner tier low" text. (`custom_ui/FormUpgradeScreen.java:48-59,456-478`)

**Altar: fuel, catalysts, JEI, recipes**

- The screen has 12 slots: 0–8 are the 3×3 input, 9 is the catalyst, 10 is fuel and 11 is the output (the output slot can only be taken from, not placed into); the window is 174×166, the progress bar 43×9 and the fuel bar 43×3, and the fuel bar shows full at 102400. (`custom_ui/AltarCraftUIHandler.java`, `custom_ui/AltarCraftUI.java:67-83`)
- The fuel table currently holds only Untreated Moondust = 800; each tick at most 1 fuel item is converted into fuelTime, and while a recipe runs it is consumed via `fuelUsage(progress)` (1 per tick by default, the total fuel is spread exactly across ticks); with no fuel everything pauses and nothing is double-charged; the output appears only when progress reaches `time`, and extra outputs spawn as item drops above the Altar. (`blocks/block_entity/AltarBlockEntity.java:309-346`, `recipes/altar/AltarRecipe.java:16-31,73-80`)
- A recipe can be resumed: progress is kept only when the recipe is the same and the total duration is equal, otherwise progress resets to zero; when crafting becomes impossible (output slot full, missing ingredients, `canCraft` fails) the current recipe and progress are cleared immediately and no more fuel is burned. (`ef56dd5`, `e8bbf6c2`, `AltarBlockEntity.java:219-279`)
- The catalyst slot (slot 9) only takes part in matching and is not consumed; recipe JSON supports `time` (ticks, default 200), `moondust_cost` (number of whole Moondust, ×800 = total fuel, default -1), `fuel_cost` (per tick, default 1), `catalyst` and `require_advancement` (reserved; none of the 37 built-in recipes currently uses it). (`recipes/altar/AltarShapedRecipe.java`/`AltarShapelessRecipe.java:130-159`; 37 recipes = 24 in `recipes/altar/` + 13 in `recipes/`)
- There is exactly one built-in recipe, "Morphscaled Food" (`shape_shifter_curse_fabric:altar/morph_scale_food`, 200 ticks, 1 fuel per tick); it is registered by `SSCEvent.BEFORE_APPLY_RECIPE` and supplies a virtual output to JEI; food that already carries the shaping marker does not match again. (`recipes/altar/RegBuiltinAlterRecipe.java:11-88`)
- JEI integration: registers the `ALTAR_SHAPED` / `ALTAR_SHAPELESS` categories, the Altar block as a recipe catalyst, item-info text for the 7 Catalyst Cores, and two TransferHandlers for one-click slot filling (they first empty the Altar slots and return the items to free player slots or drop them). (`integration/jei/**`, `d384b88d`)

**Active skill keys and triggering**

- New `key.shape-shifter-curse.active_skill_1..6` (default `GLFW_KEY_UNKNOWN`, i.e. unbound) plus the `active_skill`/`scroll`/`prev`/`next` switching keys; a perk's active ability references these keys through the `key` field of `active_self` / `charge_action` in its power JSON (mostly key 1 and key 2), and cooldown and cost are defined in the power (e.g. Wingbeat has a 40-tick cooldown and costs 1 hunger; Echolocation has a 400-tick cooldown; Frost Dive has a 160-tick cooldown; Soul Excitation has a 600-tick cooldown). (`client/ShapeShifterCurseFabricClient.java:285-310`, `powers/perks/{bat_wingbeat,bat_echolocation,snow_fox_frost_dive,anubis_wolf_soul_excitation}.json`)
- What 1.9.2 players will notice: 1.9.2 had no perk tree, no Altar/Tuner, no active skill keybinds, every trinket was crafted instantly at a crafting table, and there were no resources such as "Moondust fuel/Glint Prism"; after upgrading, old forms and trinkets are kept, but perk trees start from zero, the 13 basic trinkets must be remade through the Altar, and active skill keys must be bound manually. (`git ls-tree a96f557d -- src/main/java/net/onixary/shapeShifterCurseFabric/perk` is empty; `git log -S"active_skill_1"` first appears in `00a901d0`; old saves without the NBT key default to an empty tree in `player_form/utils/PlayerFormComponent.java:90,172-189,244-256`)

### 5.9 Datapack notes (for modpack authors)

- **Power files**: `data/shape-shifter-curse/powers` gains 117, deletes 25 and modifies 365; `data/origins/powers` deletes 60 (migrated to the SSC namespace).

  ```json
    "time": 100,
    "moondust_cost": 5
  }
  ```

  Adding `catalyst` specifies the item required in the catalyst slot (it is not consumed after matching); adding `require_advancement` requires the player to have completed an advancement first (no existing recipe uses it).

### 9.2 Gamerules and Form Recovery Mechanics

- **Gamerule `sscUseInitialForm`** (`util/ModGameRules.java`): defaults to `true` and belongs to the custom rule category "Shape Shifter Curse"; `/gamerule sscUseInitialForm false` restores the 1.9.2 vanilla start flow.
- **Initial form resolution order** (`util/InitialFormUtils.java`): the `enableInitialForm` switch → server-side `sscUseInitialForm` → weighted random over `initialFormIds` → the `SSCEvent.ON_GET_INITIAL_FORM` event may rewrite or cancel the result → if any step is disabled or returns nothing valid, fall back to `original_before_enable`. Only applies to new players who have not yet chosen a form.
- **Config example** (the higher the weight, the more often it is picked; entries with `weight < 1` are skipped):

```json
"initialFormIds": [
  "shape-shifter-curse:original_before_enable:1",
  "shape-shifter-curse:bat_0:2",
  "shape-shifter-curse:ocelot_0:1"
]
```
- **Form rollback history holds at most 20 entries**: `checkHistorySize(formHistory, 20)` at `player_form/utils/FormUtils.java:278,285,300,320`; the history drives golden-apple rollback, rollback when the Cursed Moon ends, returning to the previous form, and so on. Changing the form by command, Creative-mode inhibitors/transformation books and legacy patron transformations clear the history (`eeca25ee`); repeated transformations get overflow-safe history handling (`ce013080`); strong-inhibitor cross-tier downgrades now use a single-parameter stack-style update (`438f2dbc`).
- **Automatic rollback on login**: when entering the game and before transforming, the mod checks whether the current form is still usable (`NeedCheckUsableForm`) and automatically rolls back to the previous form when it is not (`52637c03`); on death/respawn the form component is copied with `ALWAYS_COPY`, so the form is never lost.
- **Clearing the transformation effect**: normal/enchanted golden apples and the 3 inhibitors clear the "transformation effect"; milk buckets are explicitly ineffective and produce a hint (`db2b5dc9`; `mixin/ItemStackMixin.java`, `lang/*`). A form in the Initial Phase can roll back to the previous form by eating a golden apple, and no longer requires Instinct <10% (`88b00e99`, `4f0377bb`).
- **Command entry point** `/shape_shifter_curse` (`command/ShapeShifterCurseCommand.java`):

| Command branch | Permission | Description |
|---|---|---|
| `set_form` / `transform_to_form` / `set_dynamic_form` / `transform_to_dynamic_form` / `set_sub_form` / `transform_to_sub_form` | Level 2 | Admin set/forced transformation; supports main forms, datapack forms and sub-forms (`FormArgumentType`) |
| `jump_to_next_cursed_moon` / `world_time set\|add` / `adjust_feral_item_loc` | Level 2 | World and debug helpers (skip time, adjust where FERAL holds items) |
| `keep_original_skin` / `set_form_color` / `form_color menu·save·load·delete·config·list` | Level 0 | Player self-service: keep the original skin, edit/save form color schemes |
| `patron_info` | Level 0 | Look up your own patron verification info |
| `debug ...` | Debug level 1–3 | See 9.5; gated by the `disableAllDebug` master switch |

### 9.3 Origins Migration

- **Dependency facts**: `origins-fabric` was already commented out in the 1.9.2 `build.gradle`, and this range does not change the dependency graph; SSC still depends on Apoli (`io.github.apace100:apoli`), while `extra-origins`/`origins-classes` are only `modCompileOnly`. **Servers do not need to install the Origins mod.** Internally SSC keeps a vendored Origins compatibility implementation (`integration/origins/`: Origin commands, OriginComponent, badges, spawn eggs, etc.); this range only migrated keybinds (`00a901d0`) and adjusted one piece of logic (`b304baa0`).
- **Migration completed in this range**:

| Item | 1.9.2 | 1.10.0 | Evidence |
|---|---|---|---|
| Power/Action/Condition types | `origins:` namespace | `apoli:` (all SSC-owned resources re-prefixed) | `be93f1ab` |
| Tags | `origins:meat` etc. | Copied over to `shape-shifter-curse:`; the old tag directory is kept | `be93f1ab` |
| DamageType | `data/origins/damage_type/` | New `data/shape-shifter-curse/damage_type/`; old files kept for compatibility | `9bd39acd`, `cc97ec37` |
| Origins built-in powers | Present | Removed (`89901e02`); unused type `barehand_digging` deleted (replaced by `can_barehand_digging`), 43 power types added | `89901e02`, registry |
| Keybinds | `key.origins.primary_active` (default G) etc. | `key.shape-shifter-curse.active_skill_1..6` (all unbound by default) | `00a901d0` |
| Resource count | 84 files under `data/origins/` | 24 (badges, layers, tags, legacy damage-type compatibility); `data/shape-shifter-curse/powers/` 450→468 | Resource directory comparison |

- **Not done yet**: fully removing the Origins code is post-1.10.0 work (the 5-step plan in `dev/remove_origins_plan.txt`; `b304baa0` states outright that work starts after 1.10.0 and the new forms ship), so 1.10.0 still keeps the `data/origins` directory and the compatibility code.
- **For old worlds/datapacks**: form data in old saves lives in SSC's own component and does not depend on Origins save data, so upgrading does not lose forms; old keybinds (`key.origins.*`) do not migrate to the new keybinds and players must rebind them; custom datapacks that reference `origins:` tags/damage_types can still read the compatibility files in 1.10.0, but migrating to `shape-shifter-curse:` is recommended; datapacks that reference the old power type `barehand_digging` will break.
- **Upgrade checklist (server owners/modpack authors)**: 1) Back up the world and `config/`; the old `enableNewStartBook` key is ignored, so no manual deletion is needed. 2) Migrate `origins:` types/tags in old datapacks per the table above. 3) Remind players to rebind their active skill keys (the old `key.origins.*` no longer works). 4) Switch dependencies to Fabric Loader 0.19.3+, Fabric API 0.92.11+1.20.1 and GeckoLib 4.8.4 (`gradle.properties`, Chapter 7).

### 9.4 Addon / Datapack Developer Interfaces

- **Event API (`event/SSCEvent.java`, 9 events in total)**: all Fabric Events, some of them "read + rewritable" — `FORM_CHANGE_START` / `FORM_CHANGE_END` (before/after a form switch, `3c8dec38`; passes the player, old form and new form); `TRANSFORM_MANAGER_SET_FORM` (can rewrite the final target form, `2c5ca331`, `988e5f4f`); `CURSED_MOON_BEGIN` / `CURSED_MOON_END` (`08289579`); `ACCESSORY_EQUIP` / `ACCESSORY_UNEQUIP` (trinket equip/unequip, `386d709f`); `ON_GET_INITIAL_FORM` (can rewrite/cancel the initial form, `2d189e59`); `BEFORE_APPLY_RECIPE` (register/rewrite before a recipe applies, `73427d02`). Addon mods should listen to events instead of mixin into form internals.
- **Datapack forms (DynamicForm)**: `player_form/FormDataPackReloadListener.java:19,26,45` reads two datapack directories — `data/<namespace>/ssc_form/*.json` (datapack-defined custom forms, `DynamicForm.fromJson`) and `data/<namespace>/origins_power_extra/*.json` (appends Powers to existing forms; fields `TargetLayerID`, `TargetOriginsID`, `ExtraPowers`). In 1.9.2 form extensions went through the `PlayerFormDynamic` class; 1.10.0 makes them purely data-driven; the `builtin_controller_data` style in old form model json fails silently (see Chapter 7 for details).
- **Network packets**: `networking/` contains only 4 classes — `ModPackets`, `ModPacketsC2S`, `ModPacketsS2C`, `ModPacketsS2CServer` — carrying form/Instinct/Perk/Cursed Moon data sync; 1.10.0 adds UUID null checks (`7b29fc68`, `c0a23e0d`) and instant Power/Perk sync (`f5748c2c`, `f0f849c0`), and fixes the "one packet sent every tick" problem (`5b5b9f96`). **Server and client must run the same version**, otherwise the symptom is skills/forms never refreshing; there is no public protocol documentation, so addons should not roll their own packets.
- **Utilities and observation points**: `util/Accessory/CurioUtils` and `DefaultAccessory` provide Curios trinket access helpers; the externally observable hooks are the events above; internally there is `DataDumper` (animation/model data export) and `util/test/NetWorkTest` (network packet size test), both `[Dev builds only]`.
- **Build/dependency changes**: in `gradle.properties`, Loader `0.16.10→0.19.3`, `fabric_api_version=0.92.11+1.20.1` added, `owo_version` removed, `azurelib_version` deleted in favor of `geckolib_version=4.8.4` (see Chapters 1 and 7 and `build.gradle` for details).
- **Rendering API caveat**: multi-layer rendering was temporarily removed and `getPlayerAllFormRenderer` changed from a list to a single-form renderer (`eb932dfc`); addons that rely on overlay layers/sub-form layers need to adapt.

### 9.5 Offline Patron Verification and Debug Commands

- **Offline verification mechanism**: patron status is proven entirely locally — an Ed448 signature inside the `AuthFile`, checked against a built-in public key, with no network access (`util/Verify/`: `AuthFile`, `AuthClient`, `AuthServer`, `AuthUtils`, `KeyManager/`, `KeySegment`, `PatronDataSegment`, `DebuggerDataSegment`, `VerifyEvent`); the signing tools live in `tools/SignSystem/{Ed448,RSA}`. The signature algorithm moved from RSA-4096 to Ed448 (`49597eb7`): key segments shrank from 1536 to 285 bytes and a whole verification file from about 1.6 KB to 400 B, while equivalent security rose from 128–152 to 224 bits.
- **Reliability work**: key revocation and expiry management (`c9b3628a`), expiry checks on the patron data segment (`75e4cc79`), removing stale `PATRON_AUTH_DATA` before verification (`4c3d0db9`), forced re-read of verification file parameters (`f888f15a`). 1.10.0 removed both the "sub-forms require a patron" restriction and the automatic AuthFile download/upload system (`496e1cb2`), which is now triggered manually by command.
- **Impact on server owners**: the server needs no network access and no extra configuration; after upgrading an old AuthFile may stop working — use `/shape_shifter_curse debug reupload_auth_file` or delete the local cache and rejoin; leave the 6 `[Obsolete]` Patron config options at their defaults, changing them has no effect.
- **Debug commands and permissions** (`DebuggerUtils.getDebuggerLevel`): permission-level 2 players = level 1; `enableDebugCommand=true` = level 2; dev environment = level 3; an AuthFile can add more levels on top; `disableAllDebug=true` outright forbids every debug command (the rescue switch when the permission system misbehaves).

| Debug subcommand | Purpose |
|---|---|
| `debug dev_command` | Test the dev command entry point |
| `debug clear_player_{form,skin,minion,mana}_data` | Clear the form/skin/minion/mana data of the given player (troubleshooting) |
| `debug su <level>` | Temporarily raise the debug level (-1–4) |
| `debug set_form` | Set a form directly, ignoring the rules (for debugging) |
| `debug reupload_auth_file` | Re-fetch/upload the patron verification file |

**Do not enable `enableDebugCommand` on production servers, and do not give regular players `debug su` permission.**

### 10.3 The "Fact Correction" Checklist (Traps to Avoid When Writing the Wiki)

1. **Origins dependency**: back in 1.9.2, SSC did **not** treat Origins as a required dependency (in `fabric.mod.json` it was only ever listed under breaks). The 1.10.0 change is "the vanilla powers/data copied from Origins into the mod were deleted", not "the Origins dependency was removed". Meanwhile **the Origins → SSC keybind, DamageType and Tag migration landed in 1.10.0**, so old datapacks that reference `origins:` resources directly need attention.
2. **"Models fully migrated to GeckoLib"**: `248cd770` ("replace all azurelib formats") only changed the plugin metadata of the 51 Blockbench project files under `3d_models/` in the repo, and **players cannot see that**. What actually affects players is `66837b32`: the runtime rendering library went AzureLib → **GeckoLib 4.8.4**, which changes the installation requirements (GeckoLib 4.x becomes mandatory).
3. **The all-form model rework is unreleased**: the 43 `*_anim.bbmodel` / 30 gltf files reworked after September were **not exported to the runtime `geo/`**, so the appearance players see in 1.10.0 is still the old models (only blinking eye bones, two sub-forms and test models were added). Do not write "model rework" into the 1.10.0 changelog.
4. **Third-party rendering compatibility is not new in 1.10**: compatibility logic for Iris/shaders, ImmediatelyFast, Better Combat and first-person model rendering already existed in 1.9.2. What 1.10.0 actually adds is compatibility with **CustomPlayerModels, CarryOn, SlashBlade and BOP cobwebs**.
5. **The magic system (keybind wheel/mana) is unreleased**: the code and UI are WIP, the author explicitly paused work in October, and players cannot use it in 1.10.0. Do not write it up as a new feature.
6. **Multi-layer rendering was temporarily removed**: a player only renders one form renderer, so appearances that rely on overlay layers/sub-form layers are unavailable for now; addon mods need to adapt to the changed interface signatures.
7. **The 13 base trinkets now use Altar crafting**, and their old crafting-table recipes no longer work; the "+" versions are 12 items (11 trinkets + Bottled Snowfall+), plus the Explosive Charm Paper.
8. **Active skill keys 1–6 are unbound by default** (`GLFW_KEY_UNKNOWN`), so the wiki must say "bind them yourself in the Controls menu", or players will think something is broken.
9. **Milk no longer removes the curse**; proper means such as golden apples/inhibitors are required, and the UI shows a hint.
10. **Obtaining sub-forms**: after reaching the corresponding tier-3 form, hold the Ripple Mirror (long-press 1.8 seconds) to open the "Mirror Reflection" selection screen; switching costs 1 mirror. This is not the 1.9.2 form-reselection menu.
11. **New sub-form naming**: `bat_3_sub_avali` officially reads "羽族（Avali）" in Chinese and `snow_fox_3_sub_marbled_polecat` officially reads "虎鼬（Marbled Polecat）"; the old "白鼬" (Stoat) version has been renamed and redone, so do not keep a Stoat page on the wiki.
12. **Phase naming**: every form phase moves from "Phase 0/1/2" to "Initial/Phase 1/Phase 2" (Permanent/final form unchanged); keep it uniform across the whole wiki.
13. **Resource pack/form pack authors**: tail/wing controllers in the old `builtin_controller_data` format are **not read at all** in 1.10.0 (no error, silent failure), and must switch to `animation_system` + `animation_system_config`.
14. **Test leftovers**: `_test_perk01.json`, `test_power.json`, `form_long_cat_test.geo.json`, `test_textures.png` ship with the jar, so do not include them on the wiki; `technical_form` is an internal form that cannot be selected.
