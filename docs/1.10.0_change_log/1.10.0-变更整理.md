## 一、版本范围与整理方法

### 1.1 起止版本怎么定的

仓库没有 git tag，GitHub Releases 也是空的，因此用两条独立证据交叉确定 1.9.2 的发布点：

1. `build/libs/` 中历史构建产物的时间戳：`shape-shifter-curse-1.9.2.jar` 构建于 **2026-06-14 12:27**；`1.9.2-nts` 于 06-23、`1.10.0-beta` 于 10-26。
2. 提交信息 `89901e02`（2026-06-14 17:21）明确写"既然 1.9.2 已经发布了，还是把 origins 自带的 power 移除吧"——该提交及之后的提交都不属于 1.9.2。

因此 **1.9.2 发布点 = `a96f557d`（2026-06-14 10:52，`1.9.2` 版本号后的最后一个 master 提交）**，**1.10.0 范围 = `a96f557d..b6a03f01`（HEAD，2026-10-26）**。

## 二、总览：1.10.0 相比 1.9.2 的玩家视角大图

**一句话总结**：1.10.0 不是一次内容小补丁，而是"变形系统重写 + 形态成长玩法（Perk 技能树 / 幻形祭坛 / 形态调谐信标）+ 两个新子形态 + 全量本地化修缮"三线并进的大版本；同时完成渲染库（AzureLib→GeckoLib）迁移，安装要求有变化。

### 2.1 新玩法（玩家能"做新的事"）

1. **形态技能树（Perk）**：蝙蝠/美西螈/豹猫/狐狸/雪狐/阿努比斯狼/蜘蛛的 3 阶形态与两个子形态各有一棵独立技能树（9 棵树共 68 个节点），消耗经验点或微光棱柱解锁，主动技能绑定数字键 1~6。[所有玩家，需先推进到终态]
2. **幻形祭坛 + 形态调谐信标**：两个新方块，构成一条新的合成/养成链。**幻形祭坛**是"月尘燃料 + 催化剂槽"的嬗变方块：13 件基础形态饰品改为在此合成、12 件饰品可升级为"+"、7 种催化核心与微光棱柱等材料在此产出、任意食物可做成塑形食物。**形态调谐信标**由祭坛产出，右键打开形态调谐界面加点；信标基座铺得越高（1~4 层）可点的技能树阶数越高。[所有玩家]
3. **形态升级物品（"+" 系列）**：12 件旧物品获得"+"升级版（11 件形态饰品 + 瓶装暴雪+ 手持工具），通过祭坛 + 对应催化核心升级获得（催化核心不消耗）；另有 1 件新升级链物品爆炎符纸（燃火符纸 + 灵魂沙）。[所有玩家]
4. **七种催化核心 + 咒符纸 + 新武器/工具**：密林/丝网/冻霜/磷火/浪涌/沙丘/暗夜催化核心；爆炎、药水（治疗/伤害/中毒）符纸；复合动能弓、石墨烯薄刃、波纹之镜、蛛丝弹、微光棱柱等。[所有玩家]
5. **两个新子形态**：蝙蝠 3 的"羽族 / Avali"、雪狐 3 的"虎鼬 / Marbled Polecat"，各自有独立外观、动画与玩法（羽族偏飞行、虎鼬有长脖子 IK 与站立 Idle）。[获该形态的玩家]
6. **子形态选择界面"镜中倒影"**：形态达到 3 段后可选择子形态。[形态：bat_3 / snow_fox_3]
7. **幻形者之书成为唯一书籍界面**：旧 owoLib 版的书与入门书界面连同配置项 `enableNewStartBook` 一起删除；书内新增"专属饰品/工具"区块与右上角诅咒之月图标，书与形态卷轴可放雕纹书架。调色菜单 V2 在 1.9.2 就已有完整实现，本次只修 2 个 Bug（子形态渲染、强调色反色）并支持 E 键关闭。[所有玩家]
8. **主动能力快捷键 1~6**：为 perk 主动技能新增按键。[所有玩家]
9. **初始形态配置 / Gamerule**：服务器可指定玩家开局形态，并新增 `sscUseInitialForm` 游戏规则。[服务端/整合包]

### 2.2 机制改动（旧玩家能"感觉到差异"）

1. **变形系统内核重写**：形态数据化（DynamicForm/数据包形态）、本能（Instinct）逻辑重做、形态回退/恢复（登录自动回退、最多 20 条回退历史）、诅咒之月行为重写（当晚无法睡觉、可配置是否转换）。[所有玩家]
2. **渲染库 AzureLib → GeckoLib**：必须安装 GeckoLib 4.x（4.8.4），AzureLib/AzureLibArmor 不再需要，GeckoLib 5.x 会阻止启动；jar 不再内置渲染库。[所有玩家]
3. **形态阶段命名**："0/1/2 阶段"改为"初始/第一/第二阶段"；形态书里的"专属饰品/工具"从长文本拆成独立字段展示。[所有玩家]
4. **本地化大改**：英式英语 en_gb 补全到 1020 键并英式化（该文件 1.9.2 已存在，494 键）；en_us 经历大规模语法/术语校正；俄语补充；中文富文本配色统一。[所有玩家]
5. **形态体型改由数据/属性控制**：删除全部 `*_scale.json` power（scalePower 移除），部分形态体型上调。[形态：allay_sp / anubis_wolf / axolotl / snow_fox_3 / familiar_fox_3 等]
6. **牛奶不再能解除咒文**：需金苹果/抑制剂等正规手段，界面会提示。[所有玩家]
7. **多重 layer 渲染临时移除**：一个玩家只渲染单个形态渲染器；依赖叠加层的外观暂不可用，附属 mod 需适配接口变化。[所有玩家 / 附属作者]
8. **动画资源格式换代**：形态模型的 `builtin_controller_data` 被 `animation_system`+`animation_system_config` 取代，旧资源包会静默失效（尾巴/翅膀不再动）。[资源包/形态包作者]

### 2.3 平衡调整（详见第六节）

约 43 条平衡类提交：水流爆破（伤害/冷却/消耗）、美西螈湿润度与再生、feral_cat、猫的保护半径、体型上调、咒文美西螈刷新率、金苹果/抑制剂解除咒文、豹猫飞扑条件、按键分配等。逐项 before→after 见 6.1。

### 2.4 玩家可感修复

175 条修复类提交中，大量是玩家长期反馈的问题：本能条多人不同步、Power 退出重进失效（追溯近一年）、小体型卡活板门、美西螈游泳卡墙/坐椅子、长脖第一人称错位、多人尾巴/披风错乱、服务器随机崩溃、祭坛崩服、perk 死亡复活失效、成就与雕纹书架等。汇总表见 6.2。

### 4.2 机制细节

**Perk 消耗、前置与条件提示**

- 加点请求由服务端按固定顺序校验：技能树匹配 → Perk 存在且在树内 → 付得起（非免费时）→ 前置全部满足 → 未拥有 → 主世界（tier>0）→ “上次使用的调谐信标”等级 ≥ 节点 tier → `canGain` → 扣费 → 记录并同步能力；创造模式或 `freePerkForms` 中的形态可跳过费用与阶数（仍看前置与树匹配）。（`perk/PerkUtils.java:103-159`）
- 两种花费：经验点（`player.addExperience(-N)`，不是等级）与物品（统计整背包可合并堆叠数、从背包扣，微光棱柱为例）；界面数量文本为“花费 / 当前拥有”，查询默认每 1 秒一次，点击解锁后 5 tick 刷新。（`util/util/cost/{XPCostType,ItemCostType,IFUSDrawableCostType}.java`、`custom_ui/FormUpgradeScreen.java:215-224,613-629`）
- “上次使用的调谐信标”只记在服务器内存（UUID → BlockPos），重启服务器、换维度或调谐器所在区块卸载后失效，需要重新右键一次信标才能继续解锁 tier>0 节点。（`blocks/FormAttunerBlock.java:33-44,89-90`）
- Perk 效果是给玩家加/摘 Apoli power（数据在 `data/shape-shifter-curse/powers/perks/*.json`）；切换形态或重登时重放已解锁 Perk 的 `onLoad`，并自动清理技能树中已不存在的 Perk（改树/删 perk 不破坏存档）。（`perk/NormalPerk.java`、`perk/PerkUtils.java:161-173`、`player_form/FormUtils.java:221,246`）

**调谐信标的等级与光柱**

- 等级完全由基座结构决定：从信标下方逐层检查 (2j+1)² 区域是否全为信标基座方块，非主世界等级直接为 0，每 80 tick（4 秒）刷新；0→N 阶播放信标激活音效、跌回 0 阶播放停用音效、等级>0 时播放环境音。（`blocks/block_entity/FormAttunerBlockEntity.java:111-136`）
- 最高 4 阶（`MAX_LEVEL = 4`）；开发期原本设计到 10 阶，因“一次检查约 1770 个方块、有卡服风险”下调，并为整合包作者保留 `allocMaxLevel()` 提高上限。（`907e5f5c`，`FormAttunerBlockEntity.java:26,32-34`）
- 光柱复用原版 `textures/entity/beacon_beam.png`：从信标向上直通建筑高度上限（最后一段渲染高度 1024）、内外半径 0.2/0.25、动画与信标一致；路径上的染色玻璃等 `Stainable` 方块参与染色，信标本体为粉紫色 `{0.902,0.373,0.945}`；等级为 0 时不渲染光柱。（`0475c915`、`06bf2689`，`blocks/block_entity_renderer/FormAttunerBeamRenderer.java`、`FormAttunerBlockEntity.java:138-140`）
- 界面不直接显示“当前信标等级”，只显示 1–4 阶的列分隔线与列顶数字（每列贴图 20×20 节点、列顶数字 11×11），当前列不可点时有“调谐器阶数不足”文本。（`custom_ui/FormUpgradeScreen.java:48-59,456-478`）

**祭坛：燃料、催化剂、JEI、配方**

- 界面共 12 槽：0–8 为 3×3 输入、9 为催化剂、10 为燃料、11 为输出（输出槽只能取不能放）；窗口 174×166，进度条 43×9、燃料条 43×3，燃料条按 102400 满格显示。（`custom_ui/AltarCraftUIHandler.java`、`custom_ui/AltarCraftUI.java:67-83`）
- 燃料表目前只有未处理月尘=800；每 tick 最多把 1 颗燃料转成 fuelTime，有配方时按 `fuelUsage(progress)` 扣（默认每 tick 1，总燃料会被精确摊到每 tick）；无燃料时暂停、不会重复计费；进度达到 `time` 才产出，额外产出以掉落物生成在祭坛上方。（`blocks/block_entity/AltarBlockEntity.java:309-346`、`recipes/altar/AltarRecipe.java:16-31,73-80`）
- 配方可续做：相同配方且总时长相同才保留进度，否则进度归零；无法制作（输出槽满、材料不足、`canCraft` 失败）时立刻清空当前配方与进度、不再烧燃料。（`ef56dd5`、`e8bbf6c2`，`AltarBlockEntity.java:219-279`）
- 催化剂槽（槽 9）只参与匹配、不消耗；配方 JSON 支持 `time`（tick，默认 200）、`moondust_cost`（整颗月尘数，×800=总燃料，默认 -1）、`fuel_cost`（每 tick，默认 1）、`catalyst`、`require_advancement`（预留，当前 37 条内置配方无人使用）。（`recipes/altar/AltarShapedRecipe.java`/`AltarShapelessRecipe.java:130-159`；37 条配方=24 条在 `recipes/altar/`+13 条在 `recipes/`）
- 内置配方仅「塑形食物」一条（`shape_shifter_curse_fabric:altar/morph_scale_food`，200 tick、每 tick 1 燃料），由 `SSCEvent.BEFORE_APPLY_RECIPE` 注册，并给 JEI 提供虚拟输出；已带塑形标记的食物不会再次匹配。（`recipes/altar/RegBuiltinAlterRecipe.java:11-88`）
- JEI 集成：注册 `ALTAR_SHAPED` / `ALTAR_SHAPELESS` 两个类别、祭坛方块作为配方催化剂、7 种催化核心的物品信息文本，并有两个 TransferHandler 一键填槽（先清空祭坛槽并把物品退回玩家空位或丢出）。（`integration/jei/**`、`d384b88d`）

### 9.2 游戏规则与形态恢复机制

- **游戏规则 `sscUseInitialForm`**（`util/ModGameRules.java`）：默认 `true`，归类在自定义规则分类 "Shape Shifter Curse"；`/gamerule sscUseInitialForm false` 即回到 1.9.2 的原版起始流程。
- **初始形态判定顺序**（`util/InitialFormUtils.java`）：`enableInitialForm` 开关 → 服务端 `sscUseInitialForm` → `initialFormIds` 加权随机 → `SSCEvent.ON_GET_INITIAL_FORM` 事件可改写/取消结果 → 任一环节关闭或无效则回退 `original_before_enable`。只对"尚未选择形态的新玩家"生效。
- **配置示例**（权重越大越常被选中，`weight < 1` 的条目会被跳过）：

```json
"initialFormIds": [
  "shape-shifter-curse:original_before_enable:1",
  "shape-shifter-curse:bat_0:2",
  "shape-shifter-curse:ocelot_0:1"
]
```
- **形态回退历史最多 20 条**：`player_form/utils/FormUtils.java:278,285,300,320` 的 `checkHistorySize(formHistory, 20)`；历史用于金苹果回退、诅咒之月结束回退、变回上一形态等。命令修改形态、创造模式抑制剂/变形书、旧赞助者变形会清空历史（`eeca25ee`）；连续变形做了防爆历史处理（`ce013080`）；强效抑制剂跨阶降级改为单参数栈式更新（`438f2dbc`）。
- **登录自动回退**：进游戏/变形前检查当前形态是否仍可用（`NeedCheckUsableForm`），不满足时自动退回上一形态（`52637c03`）；死亡/重生时形态组件按 `ALWAYS_COPY` 复制，形态不会丢。
- **解除变形效果**：普通/附魔金苹果与 3 种抑制剂可解除"变形效果"；牛奶桶明确无效并给出提示（`db2b5dc9`；`mixin/ItemStackMixin.java`、`lang/*`）。初始阶段形态吃金苹果可回退上一形态，且不再要求本能 <10%（`88b00e99`、`4f0377bb`）。
- **命令入口** `/shape_shifter_curse`（`command/ShapeShifterCurseCommand.java`）：

| 命令范围 | 权限 | 说明 |
|---|---|---|
| `set_form` / `transform_to_form` / `set_dynamic_form` / `transform_to_dynamic_form` / `set_sub_form` / `transform_to_sub_form` | 等级 2 | 管理员设置/强制变形，支持主形态、数据包形态、子形态（`FormArgumentType`） |
| `jump_to_next_cursed_moon` / `world_time set\|add` / `adjust_feral_item_loc` | 等级 2 | 世界与调试辅助（跳过时间、调整 FERAL 手持物品位置） |
| `keep_original_skin` / `set_form_color` / `form_color menu·save·load·delete·config·list` | 等级 0 | 玩家自助：保留原皮肤、编辑/保存形态配色 |
| `patron_info` | 等级 0 | 查询自己的赞助者验证信息 |
| `debug ...` | 调试等级 1~3 | 见 9.5；受 `disableAllDebug` 总开关约束 |

- **依赖事实**：`origins-fabric` 在 1.9.2 的 `build.gradle` 里就已经是注释状态，本区间没有改变依赖关系；SSC 仍依赖 Apoli（`io.github.apace100:apoli`），`extra-origins`/`origins-classes` 只是 `modCompileOnly`。**服务器不需要额外安装 Origins mod**。SSC 内部保留了一层 vendored Origins 兼容实现（`integration/origins/`：Origin 命令、OriginComponent、徽章、刷怪球等），本区间只做了按键迁移（`00a901d0`）与一处逻辑调整（`b304baa0`）。
- **本区间完成的迁移**：

| 项目 | 1.9.2 | 1.10.0 | 证据 |
|---|---|---|---|
| Power/Action/Condition 类型 | `origins:` 命名空间 | `apoli:`（SSC 自有资源全部改前缀） | `be93f1ab` |
| Tag | `origins:meat` 等 | 复制迁移到 `shape-shifter-curse:`，旧 tag 目录保留 | `be93f1ab` |
| DamageType | `data/origins/damage_type/` | 新增 `data/shape-shifter-curse/damage_type/`，旧文件保留兼容 | `9bd39acd`、`cc97ec37` |
| Origins 自带 Power | 存在 | 移除（`89901e02`）；删除未用类型 `barehand_digging`（替换为 `can_barehand_digging`），新增 43 个 power 类型 | `89901e02`、注册表 |
| 按键 | `key.origins.primary_active`（默认 G）等 | `key.shape-shifter-curse.active_skill_1..6`（默认全未绑定） | `00a901d0` |
| 资源数量 | `data/origins/` 84 个文件 | 24 个（徽章、layer、标签、旧伤害类型兼容）；`data/shape-shifter-curse/powers/` 450→468 | 资源目录对比 |

- **未完成**：彻底移除 Origins 代码是 1.10.0 之后的工作（`dev/remove_origins_plan.txt` 的 5 步计划；`b304baa0` 明说"等 1.10.0 和新形态发布后开工"），因此 1.10.0 仍保留 `data/origins` 目录与兼容代码。
- **对旧世界/数据包**：旧存档中的形态数据存在 SSC 自己的组件里，不依赖 Origins 存档，升级不会丢形态；旧按键绑定（`key.origins.*`）不会迁移到新按键，需要玩家重绑；自定义数据包若引用 `origins:` 的 tag/damage_type，1.10.0 仍能读取兼容文件，但建议迁移到 `shape-shifter-curse:`；引用旧 power 类型 `barehand_digging` 的数据包会失效。
- **升级清单（服主/整合包作者）**：① 备份 world 与 `config/`，旧 `enableNewStartBook` 键会被忽略无需手删；② 旧数据包里的 `origins:` 类型/标签按上表迁移；③ 提醒玩家重绑主动技能键（原 `key.origins.*` 不再生效）；④ 依赖换成 Fabric Loader 0.19.3+、Fabric API 0.92.11+1.20.1、GeckoLib 4.8.4（`gradle.properties`、第七章）。

### 9.4 附属 / 数据包开发者接口

- **事件 API（`event/SSCEvent.java`，共 9 个）**：均为 Fabric Event，部分"读 + 可改写"——`FORM_CHANGE_START` / `FORM_CHANGE_END`（形态切换前后，`3c8dec38`；传玩家、旧形态、新形态）；`TRANSFORM_MANAGER_SET_FORM`（可改写最终目标形态，`2c5ca331`、`988e5f4f`）；`CURSED_MOON_BEGIN` / `CURSED_MOON_END`（`08289579`）；`ACCESSORY_EQUIP` / `ACCESSORY_UNEQUIP`（饰品装备/卸下，`386d709f`）；`ON_GET_INITIAL_FORM`（可改写/取消初始形态，`2d189e59`）；`BEFORE_APPLY_RECIPE`（配方应用前注册/改写，`73427d02`）。附属 mod 应监听事件而不要 mixin 形态内部。
- **数据包形态（DynamicForm）**：`player_form/FormDataPackReloadListener.java:19,26,45` 读取两个数据包目录——`data/<命名空间>/ssc_form/*.json`（数据包自定义形态，`DynamicForm.fromJson`）与 `data/<命名空间>/origins_power_extra/*.json`（给已有形态追加 Power，字段 `TargetLayerID`、`TargetOriginsID`、`ExtraPowers`）。1.9.2 的形态扩展走 `PlayerFormDynamic` 类，1.10.0 改为纯数据驱动；旧形态模型 json 的 `builtin_controller_data` 写法会静默失效（详见第七章）。
- **网络包**：`networking/` 只有 4 个类——`ModPackets`、`ModPacketsC2S`、`ModPacketsS2C`、`ModPacketsS2CServer`，承载形态/本能/Perk/诅咒之月数据同步；1.10.0 增加 UUID 空值校验（`7b29fc68`、`c0a23e0d`）、Power/Perk 即时同步（`f5748c2c`、`f0f849c0`），并修复了"每 tick 都发一个包"的问题（`5b5b9f96`）。**服务端与客户端必须同版本**，否则表现为技能/形态不刷新；没有对外协议文档，附属不建议自组包。
- **工具与观测点**：`util/Accessory/CurioUtils`、`DefaultAccessory` 提供 Curios 饰品访问辅助；对外可观测点即上述事件；内部有 `DataDumper`（动画/模型数据导出）与 `util/test/NetWorkTest`（网络包体积测试），均为 `[仅开发版]`。
- **构建/依赖变化**：`gradle.properties` 的 Loader `0.16.10→0.19.3`、新增 `fabric_api_version=0.92.11+1.20.1`、`owo_version` 移除、`azurelib_version` 删除并改为 `geckolib_version=4.8.4`（详见第一章、第七章与 `build.gradle`）。
- **渲染 API 注意**：多重 layer 渲染被临时移除，`getPlayerAllFormRenderer` 由列表改为单形态渲染器（`eb932dfc`），依赖叠加层/子形态 layer 的附属需要适配。

### 9.5 赞助者离线验证与调试命令

- **离线验证机制**：赞助者身份靠本地 `AuthFile` 中的 Ed448 签名 + 内置公钥验证完成，不联网（`util/Verify/`：`AuthFile`、`AuthClient`、`AuthServer`、`AuthUtils`、`KeyManager/`、`KeySegment`、`PatronDataSegment`、`DebuggerDataSegment`、`VerifyEvent`）；签名工具在 `tools/SignSystem/{Ed448,RSA}`。签名算法从 RSA-4096 换成 Ed448（`49597eb7`）：密钥段 1536→285 字节、整份验证文件约 1.6KB→400B，等效安全 128~152→224 bit。
- **可靠性改造**：密钥熔断与过期管理（`c9b3628a`）、赞助者数据段过期检查（`75e4cc79`）、验证前先移除 `PATRON_AUTH_DATA` 旧数据（`4c3d0db9`）、强制重读验证文件参数（`f888f15a`）。1.10.0 移除了"子形态需要赞助者"的限制以及自动下载/上传 AuthFile 的系统（`496e1cb2`），改为命令手工触发。
- **对服主的影响**：服务端不需要联网、不需要额外配置；升级后旧 AuthFile 可能失效，用 `/shape_shifter_curse debug reupload_auth_file` 或删除本地缓存后重进即可；`[Obsolete]` 的 6 个 Patron 配置项保持默认即可，修改无效果。
- **调试命令与权限**（`DebuggerUtils.getDebuggerLevel`）：权限 2 玩家 = 1 级；`enableDebugCommand=true` = 2 级；开发环境 = 3 级；AuthFile 可再叠加等级；`disableAllDebug=true` 直接禁止全部调试命令（权限系统异常时救援）。

| 调试子命令 | 作用 |
|---|---|
| `debug dev_command` | 测试开发命令入口 |
| `debug clear_player_{form,skin,minion,mana}_data` | 清空指定玩家的形态/皮肤/召唤物/魔力数据（排障） |
| `debug su <level>` | 临时提升调试等级（-1~4） |
| `debug set_form` | 无视规则直接设置形态（调试用） |
| `debug reupload_auth_file` | 重新获取/上传赞助者验证文件 |

**正式服不要开启 `enableDebugCommand`，也不要给普通玩家 `debug su` 权限。**

### 10.3 必查的"事实纠错"清单（写 wiki 时别踩）

1. **Origins 依赖**：SSC 在 1.9.2 就**没有**把 Origins 作为必需依赖（`fabric.mod.json` 里一直只在 breaks 列出）。1.10.0 的变化是"删掉了从 Origins 复制进模组内部的原版 power/数据"，不是"移除 Origins 依赖"。而 **Origins 的按键 → SSC 按键、DamageType、Tag 的迁移在 1.10.0 内完成**，旧数据包若直接引用 `origins:` 资源需要注意。
2. **"模型全面迁移 GeckoLib"**：`248cd770`（"全部替换 azurelib 格式"）只改了仓库 `3d_models/` 里 51 个 Blockbench 工程文件的插件元数据，**玩家看不到**。真正影响玩家的是 `66837b32`：运行时渲染库 AzureLib → **GeckoLib 4.8.4**，安装要求变化（必装 GeckoLib 4.x）。
3. **全形态模型重做未发布**：9 月后重做的 43 个 `*_anim.bbmodel` / 30 个 gltf **没有导出到运行时 `geo/`**，1.10.0 玩家看到的外观仍是旧模型（只多了眨眼的眼骨、两个子形态、测试模型）。不要把"模型重做"写进 1.10.0 更新日志。
4. **第三方渲染兼容不是 1.10 新增**：Iris/光影、ImmediatelyFast、Better Combat、第一人称模型渲染的兼容逻辑 1.9.2 就已存在。1.10.0 真正新增的是 **CustomPlayerModels、CarryOn、拔刀剑、BOP 蛛网** 的兼容。
5. **魔法系统（按键轮盘/魔力）未发布**：代码与 UI 属 WIP，作者 10 月明确"暂时停工"，玩家在 1.10.0 中用不到。不要写成新功能。
6. **多重 layer 渲染被临时移除**：一个玩家只渲染一个形态渲染器，依赖叠加层/子形态 layer 的外观暂不可用；附属模组需要适配接口签名变化。
7. **13 件基础饰品改为祭坛合成**，原工作台配方不再可用；"+"版是 12 件（11 饰品 + 瓶装暴雪+），另有爆炎符纸。
8. **主动技能 1~6 键默认未绑定**（`GLFW_KEY_UNKNOWN`），wiki 必须写"需要到控制菜单自行绑定"，否则玩家会以为坏了。
9. **牛奶不再能解除咒文**，需金苹果/抑制剂等正规手段；界面会提示。
10. **子形态获取**：达到对应 3 阶形态后，用波纹之镜（长按 1.8 秒）打开"镜中倒影"选择界面，切换消耗 1 面镜子；不是 1.9.2 的形态重选菜单。
11. **新子形态命名**：`bat_3_sub_avali` 官方中文"羽族（Avali）"，`snow_fox_3_sub_marbled_polecat` 官方中文"虎鼬（Marbled Polecat）"；旧"白鼬"版本已改名重做，wiki 不要保留白鼬页。
12. **阶段命名**：所有形态阶段从"0/1/2 阶段"改为"初始/第一/第二阶段"（永久/终态不变），wiki 全站统一。
13. **资源包/形态包作者**：旧 `builtin_controller_data` 格式的尾巴/翅膀控制器在 1.10.0 **完全不读取**（无报错、静默失效），必须改用 `animation_system` + `animation_system_config`。
14. **测试残留**：`_test_perk01.json`、`test_power.json`、`form_long_cat_test.geo.json`、`test_textures.png` 会随 jar 发布，wiki 不要收录；`technical_form` 是不可选的内部形态。
